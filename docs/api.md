## 1. 표기

- **키는 `snake_case`.** 데이터 계약과 같은 모양을 쓴다 — 세 저장소가 표기를 통일하는 편이 싸다
- **열거 값은 소문자 `snake_case`.** 서버 내부 `enum`은 자바 관례대로 대문자지만 **그 이름은 API로 새지 않는다.** API 층이 변환한다
- 시간·날짜를 응답에 담지 않는다. 게임 내 날짜는 요청이 정한다

## 2. 버전

경로에 박는다. `/api/v1/...`

major가 바뀌면 경로가 바뀐다. 필드를 **더하는** 것은 major를 올리지 않으니, 클라이언트는 **모르는 필드를 무시**해야 한다.

## 3. 인증

**없다.** 프로토타입이라 `save_id`를 클라이언트가 그대로 보낸다.

이 상태로는 남의 세이브를 조회할 수 있다. **알고 받아들인 빚이다** — 배포가 실제로 필요해질 때 갚는다. 그전까지 이 서버를 공개 인터넷에 올리지 않는다.

## 4. `GET /api/v1/saves/{save_id}/days/{day_number}/guests/{guest_id}/visit-state`

손님이 **오늘 어떤 상태로 오는가**를 돌려준다.

**읽기 전용이고 부수 효과가 없다.** 같은 경로는 언제 불러도 같은 답을 낸다 — 상태를 저장하지 않고 씨앗에서 다시 계산하기 때문이다. 재시도해도 안전하고, 캐시해도 안전하다.

### 경로 변수

| | 타입 | 설명 |
|---|---|---|
| `save_id` | string | 세이브 식별자. 비어 있으면 400 |
| `day_number` | integer | 게임 내 날짜. **1부터.** 0 이하면 400 |
| `guest_id` | string | 데이터 계약의 손님 슬러그 |

### 200

```json
{
  "save_id": "save-1",
  "day_number": 1,
  "guest_id": "guest_dusty_patrol_01",
  "hunger": 67,
  "condition": "normal",
  "mood": "elated",
  "wallet": 24,
  "needs": ["special", "filling"]
}
```

| 필드 | 타입 | 값 |
|---|---|---|
| `hunger` | integer | 0~100 |
| `condition` | string | `normal` · `injured` · `tired` |
| `mood` | string | `gloomy` · `calm` · `elated` |
| `wallet` | integer | 오늘 이 손님이 쓸 수 있는 돈 |
| `needs` | string[] | 이번 방문의 **우선 욕구**. 1~2개, 중요한 순서다. `filling` · `restorative` · `mild` · `stimulating` · `affordable` · `special` |

요청 식별자 셋을 **되돌려 담는다.** 응답만 보고도 무엇에 대한 답인지 알 수 있게 하려는 것이다.

**응답에 없는 것**: 이름·소개·말투·취향 구간·식이 제약. 그것들은 안 바뀌므로 데이터 계약이 소유하고, **클라이언트가 자기 번들에서 `guest_id`로 읽는다.** 서버는 중계하지 않는다.

### 오류

모든 실패가 같은 모양으로 나간다. `error`는 기계가 분기할 값이고 `message`는 사람이 읽을 설명이다. **`message`에 기대어 분기하지 말 것** — 문구는 바뀐다.

| 상태 | `error` | 언제 |
|---|---|---|
| 404 | `unknown_guest` | 서버 스냅샷에 없는 `guest_id` |
| 400 | `invalid_request` | 0 이하 날짜, 숫자가 아닌 날짜, 빈 식별자 |

```json
{ "error": "unknown_guest", "message": "모르는 손님이다: guest_ashen_scout_01" }
```

### ⚠️ 404가 뜨면 대개 콘텐츠 버전 문제다

서버는 **파이프라인 `guests.json` 스냅샷**을 자기 리소스로 들고 있다. 클라이언트가 번들한 것과 **다른 스냅샷**이면 `guest_id`가 하나도 안 맞아 전부 404가 된다.

실제로 한 번 겪었다 — 클라가 손으로 쓴 목 데이터(4명)를 들고 있고 서버는 생성분(8명)을 들고 있어서, 두 집합의 겹침이 0이었다. **둘 다 `schema_version`이 1.0.0이라 형식 검사로는 안 잡힌다.**

**양쪽이 같은 산출물을 봐야 한다.** 콘텐츠를 다시 뽑으면 서버 리소스와 클라 번들을 같이 갱신한다.
