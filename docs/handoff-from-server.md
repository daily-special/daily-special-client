# 서버 쪽에서 보내는 편지

> **이건 편지지 명세가 아니다.** 클라이언트의 명세는 `AGENTS.md`와 `docs/`의 세 문서가 소유한다.
> 여기 있는 것은 그 문서들이 아직 모르는 것, 그리고 내가 당신에게 받아야 할 것뿐이다.
>
> **죽는 조건**: 4절의 답을 받으면 이 파일은 지운다. 편지는 낡아도 되지만 오래 남으면 명세인 척한다.
>
> 보낸 날: 2026-08-06 · 보낸 쪽: `daily-special-server` · `daily-special-pipeline`

---

## 1. 지금 어디까지 와 있나

**파이프라인은 끝났다.** 손님 8 · 재료 12 · 요리 10 · 대사 80이 실제로 생성돼 있다. 당신이 읽을 목 데이터는 그 축소판이다.

**서버는 골격과 도메인 첫 조각까지.** 기동되고, 오늘 상태 생성기가 있다. API는 없다 — 없는 게 의도다. 이유는 4절에 있다.

## 2. 당신이 지금 할 일은 여기 적지 않는다

1단계(목 JSON → 한글 표시 → APK)는 `AGENTS.md`와 `docs/client-design.md` 0절이 이미 갖고 있다. **여기 옮겨 적으면 두 벌이 되고, 두 벌은 반드시 어긋난다.**

한 가지만 덧붙인다. **판정을 미루지 마라.** 폰에서 한글이 깨지거나 빌드가 안 되면 그건 오늘 알아야 하는 소식이다. 웹 전환 경로가 `client-design.md` 0절에 있고, 늦게 알수록 그 문이 좁아진다. 예선 마감이 **8/10**이다.

### 2-1. 다만 지뢰 셋은 미리 알린다

문서에 없고, 밟으면 시간을 먹는 것들이다. 이 저장소의 CI를 내가 만들어서 아는 것이다.

**하나. `data/*.json`을 `Assets/Resources/`로 옮길 때는 복사가 아니라 이동이다.** 두 벌이 되면 어느 쪽이 진짜인지 며칠 뒤에 모른다. 그리고 `.github/workflows/check.yml`이 지금 `data/`를 읽고 있으니 **경로를 같이 고쳐야 CI가 통과한다.** `client-design.md` 4절의 위치 설명도 같이 고친다.

**둘. `Assets/` 아래 파일은 `.meta`도 함께 커밋해야 한다.** CI가 누락을 잡는다. 빼면 씬과 프리팹의 참조가 조용히 끊기는 게 이 저장소의 1번 사고 유형이라 일부러 검사를 걸어뒀다.

**셋. Newtonsoft는 기본 설치가 아니다.** `com.unity.nuget.newtonsoft-json`을 Package Manager로 넣어야 한다. Unity 기본 `JsonUtility`로는 이 계약을 못 읽는다 — `snake_case` 매핑이 없다.

## 3. 3단계에 넘어갈 것 — 미리 알아두면 좋은 것

손님의 **오늘 상태**(허기·컨디션·기분·지갑)를 서버가 씨앗에서 결정적으로 뽑는다. 같은 세이브의 같은 날 같은 손님이면 언제나 같은 값이다.

**클라이언트는 이걸 C#으로 이식하게 된다.** 예선 빌드는 서버를 부르지 않으니까. 만족도 엔진과 똑같은 방식이고, **명세는 서버 저장소의 `VisitStateGeneratorTest` 고정 벡터**다. 요약본은 만들지 않는다 — 두 벌이 되면 요약본이 뒤처지고, 그때 어느 쪽이 맞는지 알 수 없다.

알고리즘은 언어 중립으로 잡아뒀다. SHA-256과 SplitMix64라서 C#에서 같은 값이 나온다.

**지금 미리 만들지 마라.** 3단계에 오면 옮길 테스트를 넘긴다.

미리 알리는 이유는 하나다 — **`Domain/`에 `.asmdef`를 걸고 `UnityEngine` 참조를 빼두는 이유가 이것이다.** 순수 C#이어야 그 테스트가 EditMode에서 돈다. 나중에 떼려면 비싸고, 지금 나누면 공짜다.

## 3-1. ⭐ 요청 — 목 데이터를 파이프라인 생성분으로 갈아타 달라 (2026-08-06 추가)

**1단계 go를 확인했다. 그리고 붙여보려다 막히는 것을 찾았다.**

지금 번들된 `Assets/Resources/*.json`은 `out/mock/`의 **손으로 쓴 고정 표본**이다. 파이프라인이 실제로 생성한 것은 `out/packages/1.0.0/`에 따로 있고, **두 집합의 `guest_id`가 하나도 겹치지 않는다.**

```
파이프라인 생성분   8명   guest_dusty_patrol_01 · guest_pale_clerk_02 · ...
지금 번들(목)      4명   guest_ashen_scout_01 · guest_ember_brawler_01 · ...
겹침               0
```

이대로 두면 서버가 `guest_id`로 조인할 수 없다. 클라가 보내는 모든 손님이 404가 된다.

더 큰 문제는 따로 있다. 목을 계속 쓰면 **게임이 손으로 쓴 손님 4명으로 나간다.** 이 게임의 AI 차별점이 "LLM이 만든 페르소나"인데 그걸 빼고 제출하는 셈이다. 목은 파이프라인이 콘텐츠를 못 뽑던 시절의 임시물이었고, 지금은 다 뽑혀 있다.

**부탁**: `daily-special-pipeline`의 `out/packages/1.0.0/` 네 파일로 `Assets/Resources/`를 교체하고, APK에서 한 번 더 확인해 달라.

| | 지금(목) | 생성분 |
|---|---|---|
| `guests.json` | 4 | **8** |
| `ingredients.json` | 6 | **12** |
| `dishes.json` | 4 | **10** |
| `lines.json` | 5 (인사만) | **80** (전 상황) |

**봉투 구조와 `schema_version`(1.0.0)이 같아서 코드는 안 고쳐도 된다.** 파일만 갈아끼우면 되고, 화면에 뜨는 이름이 바뀔 뿐이다. `client-design.md` 4절의 개수와 설명도 같이 고쳐 달라 — 지금 값이 목 기준이다.

## 3-2. ⭐ 요청 — 폰트 아틀라스를 넓혀 달라 (2026-08-07 추가)

**3-1 교체분을 받아 검사했다. 조인은 완벽하다** — `guest_id` 8개가 서버 스냅샷과 정확히 일치한다. 고맙다.

**그런데 폰트에 없는 글자가 들어왔다.**

생성분 전체를 아틀라스 범위(`20-7E,AC00-D7A3`)로 훑었더니 **`…`(U+2026)가 11번** 나온다. 전부 `lines.json`의 `text`이고, **전부 `weary`(지친) 말투다.** 모델이 지친 어조를 말줄임표로 표현했다.

```
line_greet_weary_01              앉으니 살 것 같네…
line_order_mild_weary_01         뭐만 먹으면 더부룩해서… 가벼운 거 있을까.
line_order_affordable_weary_01   순찰비가 또 밀렸네… 배는 고프고.
```

**말투 하나가 통째로 네모(□)로 뜬다.** 구석 사례가 아니다.

이게 왜 지금까지 안 잡혔는지도 분명하다 — 지금까지 화면에 띄운 것은 **손님 이름·소개**(`guests.json`)이고 **대사는 아직 안 띄웠다.** 에뮬레이터냐 실기기냐의 문제가 아니라 **아직 보여주지 않은 데이터에 있는 문제다.** 당신이 놓친 것이 아니다.

**부탁 하나**: Font Asset Creator의 Character Set을 이 범위로 다시 구워 달라.

```
20-7E,A1-FF,2013-2014,2018-201D,2026,AC00-D7A3
```

`2026`이 말줄임표고, 나머지는 **다음에 나올 것들**이다 — 줄표(—·–), 홑/겹따옴표(''""), 가운뎃점(·) 등. 콘텐츠를 다시 뽑으면 또 나올 종류라 한 번에 넣는 편이 싸다. 글리프 100여 개 추가라 4096×4096에 여유가 충분하다.

`conventions.md` 6절이 지금 범위를 `20-7E,AC00-D7A3`으로 적고 있다. 그 절이 이 설정의 소유 문서이니 **구우면서 같이 고쳐 달라.**

**부탁 둘**: 확인할 때 **`weary` 말투 대사를 한 줄 화면에 띄워 달라.** 이름·소개만 보면 이 버그가 또 안 보인다. 예를 들어 `line_greet_weary_01`.

**이쪽에서도 고친다.** 파이프라인 검증 층에 "허용 문자 집합" 검사를 넣는다. 지금은 폰에 올려야 알 수 있는 버그인데, 그러면 생성 즉시 잡힌다. 위 범위 문자열은 **파이프라인 설정이 소유하게** 만들 것이다 — 두 곳이 각자 적으면 반드시 어긋난다. 값이 바뀌면 알리겠다.

## 3-3. 다음 작업 — 2단계 하루 사이클 (2026-08-07 추가)

**3-2 폰트 확장 확인했다. `weary` 대사를 실제로 띄워 본 것이 정확했다** — 이름·소개만 봤으면 그 버그는 또 숨었다.

이쪽도 진도가 나갔다. **오늘의 욕구가 붙어서 API 응답에 `needs`가 늘었다.** `docs/api.md` 사본을 갱신해 뒀다.

```json
{ "hunger": 18, "condition": "tired", "mood": "gloomy", "wallet": 10,
  "needs": ["mild", "affordable"] }
```

지치고 우울하고 돈 없는 손님이 순한 것과 저렴한 것을 원한다. 욕구는 1~2개, 중요한 순서다.

### 부탁 — 2단계를 진행해 달라

`client-design.md` 0절의 2단계, **하루 사이클 척추**다. 장보기 · 손님 1명 · 요리 · 반응.

**이게 지금 프로젝트 전체의 임계 경로다.** 예선 마감이 **8/10**인데 시연 영상은 동작하는 화면이 있어야 찍을 수 있고, 찍을 것이 이것이다.

### 임시 상태를 만들 때 한 가지만

`client-design.md` 3절이 "서버 소유 상태를 임시로 만들되 한 곳에 모아둔다"고 정해뒀다. 그 한 곳의 **모양을 위 API 응답과 같게** 해 달라.

```
hunger · condition · mood · wallet · needs
```

값은 로컬에서 아무렇게나 만들어도 된다 — **모양만 같으면 나중에 그 자리를 네트워크 호출로 바꾸는 것이 파일 하나짜리 작업이 된다.** 모양이 다르면 화면까지 따라 고쳐야 한다.

**지금은 진짜 규칙을 옮기지 마라.** 3단계 몫이고, 영상에 필요한 것은 화면에 손님이 뜨고 반응이 나오는 것이지 수치의 정확성이 아니다.

### 3단계 준비물이 둘로 늘었다 (예고)

| 서버의 이식 명세 | 무엇 |
|---|---|
| `VisitStateGeneratorTest` | 씨앗 → 허기·컨디션·기분·지갑 |
| `NeedResolverTest` | 상태 → 오늘의 욕구 |

만족도 엔진(`test_satisfaction.py` 23건)까지 하면 셋이다. **3단계에 오면 옮길 테스트를 넘긴다.** 지금 미리 만들지 마라.

`NeedResolverTest`의 첫 묶음은 설계 문서에 적힌 예시 셋을 그대로 고정한 것이다 — 몸이 안 좋으면 회복과 순한, 지갑이 부족하면 저렴, 들뜨면 특별과 포만.

## 3-4. ⭐ 3단계 이식 — 오늘 상태와 욕구 (2026-08-07 추가)

**2단계 확인했다. `LocalDayStateStore`가 정확히 부탁한 모양이다** — 필드가 API 응답과 같아서 서버를 붙이는 것이 파일 하나짜리 작업이 됐다.

이제 그 고정값을 **진짜 규칙으로 바꿀 차례다.**

### 왜 지금인가

지금은 손님 하나가 매번 같은 상태로 온다. 그러면 **이 게임의 알맹이가 화면에 안 드러난다** — LLM이 만든 손님 8명이 날마다 다른 상태로 오고, 그 상태가 오늘의 욕구를 낳는다는 것이 「하이브리드 손님 에이전트」의 전부다.

이식하면 이런 장면이 나온다.

```
도윤 · 1일차   들뜸 · 허기 67 · 지갑 24   →  특별, 포만
도윤 · 7일차   피로 · 우울 · 지갑 10      →  순한, 저렴
```

같은 손님이 다른 날 다른 것을 원한다. **시연 영상에 들어가야 할 장면이 이것이다.**

### 무엇을 옮기나

서버 저장소를 받아서 옮긴다. 공개 저장소다.

```
git clone https://github.com/daily-special/daily-special-server.git
```

| 옮길 것 | 원본 |
|---|---|
| 씨앗 접기 | `domain/visit/VisitSeed.java` |
| 난수기 | `domain/visit/SplitMix64.java` |
| 상태 생성 | `domain/visit/VisitStateGenerator.java` · `VisitNumbers.java` |
| 욕구 판정 | `domain/visit/NeedResolver.java` · `NeedNumbers.java` · `Need.java` |

**명세는 테스트다.**

```
src/test/java/com/dailyspecial/server/domain/visit/VisitStateGeneratorTest.java
src/test/java/com/dailyspecial/server/domain/visit/NeedResolverTest.java
```

이 케이스를 C#으로 옮겨 **EditMode 테스트로 전부 통과시킨다.** 통과하면 두 구현이 어긋나지 않는다. 만족도 엔진과 같은 방식이다.

**요약본을 만들지 마라.** 원본을 직접 보고 옮긴다 — 요약이 생기면 그것이 뒤처지고, 그때 어느 쪽이 맞는지 알 수 없다.

### ⚠️ 반드시 물리는 자리 하나

`SplitMix64`가 만든 64비트를 **부호 있는 값으로 읽어야 한다.** 자바의 `long`은 부호가 있고, 상한을 씌울 때 `Math.floorMod`를 쓴다. C#에서 `ulong`으로 들고 `%`를 그대로 쓰면 **전혀 다른 값이 나온다.**

```
같은 비트 0xFFFFFFFFFFFFFFFF, 상한 101
  Java  floorMod(-1, 101)                = 100
  C#    18446744073709551615UL % 101UL   =  78     ← 다른 손님이 나온다
```

C#에서는 이렇게 맞춘다.

```csharp
long v = unchecked((long)state);          // 부호 있는 값으로 읽는다
int r = (int)(((v % bound) + bound) % bound);   // floorMod
```

**고정 벡터가 이걸 잡는다.** `SplitMix64` 씨앗 0의 첫 세 값(`-2152535657050944081` 등)이 안 맞으면 여기가 틀린 것이다. 그 값들은 공개된 정본 벡터와도 같다.

### 하지 말 것

- **만족도 엔진(`test_satisfaction.py` 23건)은 아직 옮기지 마라.** 영상에 필요 없다. 상태와 욕구만으로 충분하다
- **서버 HTTP 호출을 붙이지 마라.** 예선 빌드는 오프라인이어야 한다

### 같이 해야 하는 것

**`Assets/Scripts/Domain/`과 `.asmdef`를 이번에 만든다.** `conventions.md` 1·2절이 정한 것이고, **지금이 그 순간이다** — 옮긴 규칙이 `MonoBehaviour` 안으로 들어가면 EditMode 테스트로 검증할 방법이 사라지고, 그러면 이식이 맞는지 확인할 수 없다.

그리고 `LocalDayStateStore`가 고정값 대신 이식한 생성기를 쓰게 하고, **날짜를 넘길 수 있게** 해 달라. 같은 손님의 1일차와 7일차가 다르게 나오는 것을 화면에서 보여야 한다.

### 시간

**예선 마감 8/10이다.** 이것이 끝나면 시연 영상을 찍을 수 있다. 막히면 우회하지 말고 우편함에 적어 달라 — 남은 시간에는 막힌 채로 도는 것이 제일 비싸다.

### 답 1 — 입력 DTO의 경계

**도메인은 콘텐츠 레코드를 모른다.** `evaluate`는 아래 넷만 받는다.

```
GuestPersona   ideal_ranges: {축키 → {low, high}}    dietary: [식이키]
VisitState     needs: [욕구키]                        wallet: int
ServedDish     need_tags: [욕구키]  price: int
               dietary_conflicts: [식이키]            params: {축키 → int}
ScoringNumbers 아래 4개 계수 + 축 목록
```

**전부 평범한 값과 목록이다.** `GuestRecord`·`DishRecord`가 도메인에 들어오면 계약이 바뀔 때마다 만족도 규칙이 흔들린다.

### 답 2 — 콘텐츠를 도메인 입력으로 바꾸는 자리는 `Data/`다

도메인 바깥이다. 그리고 **네 값은 콘텐츠에 없다.** 만들어서 넣어야 한다.

| 입력 | 어디서 오나 |
|---|---|
| `persona.ideal_ranges` · `dietary` | `guests.json` 그대로 |
| `dish.need_tags` · `price` | `dishes.json` 그대로 |
| **`dish.dietary_conflicts`** | ⚠️ **`dishes.json`에 없다.** 그 요리가 쓴 **재료들의 저촉 합집합**이다 (계약 9-1절) |
| **`dish.params`** | ⚠️ **콘텐츠가 아니다.** 플레이어가 슬라이더로 맞춘 값이다 |
| `state.needs` · `wallet` | 이미 이식한 `NeedResolver`·`VisitStateGenerator`의 결과 |

`dietary_conflicts`가 이 이식에서 제일 틀리기 쉬운 자리다. 요리에 그 필드가 있을 것 같지만 없다 — **유도되는 값 셋** 중 하나다.

### 들고 가야 할 수치

`project_bible.json`이 원본이다. `VisitNumbers`처럼 클래스 하나로 옮긴다.

```
need_floor                0.15    욕구 충족도의 바닥
axis_tolerance            25      이만큼 벗어나면 그 축이 0
budget_overrun_ratio      1.5     지갑의 1.5배 가격에서 예산 항이 0
dietary_violation_factor  0.1     위반 하나당 곱한다
```

**축 목록과 그 순서도 명세의 일부다.** `axis_scores` 출력 순서가 이 순서다.

```
heat(불 세기) · cook_time(조리 시간) · seasoning(간)      셋 다 슬라이더 0~100
식이: no_meat · no_alcohol · no_dairy · no_spicy
```

### 계산 (원본을 봐야 하지만 뼈대만)

```
만족 = 욕구 충족도 × 취향 일치도 × 예산 적합 × 식이 계수
```

- **욕구** — 덮은 비율. 단 `need_floor` 아래로 안 내려간다. 욕구가 없으면 1.0
- **취향** — 축마다 구간 안이면 1.0, 밖은 `axis_tolerance`까지 선형 감소, 넘으면 0. **축 사이는 곱이 아니라 평균**이다. 상위 공식이 이미 곱셈이라 축까지 곱하면 감쇠가 여섯 번 겹친다
- **예산** — 가격 ≤ 지갑이면 1.0. 넘으면 지갑의 1.5배에서 0이 되도록 선형. 지갑이 0 이하면 0.0
- **식이** — `0.1 ^ 위반수`

### 걸리기 쉬운 자리 넷

1. **취향 없는 축은 건너뛴다.** `ideal_ranges`에 키가 없으면 그 축은 채점하지 않는다. 축이 하나도 없으면 취향 일치도는 **1.0**이다 — 파라미터로는 실패할 수 없는 손님이다
2. **손님이 취향을 가진 축인데 요리에 그 파라미터가 없으면 예외를 던진다.** 조용히 넘기지 마라
3. **실수 비교는 오차를 허용한다.** 원본 테스트가 `pytest.approx`를 쓴다. C#에서도 `Within`으로 비교하라 — 정확 비교하면 마지막 자리에서 갈린다
4. **`Math.Round` 주의.** C#은 기본이 은행가 반올림이고 자바는 올림이다. 이번 이식에는 나눗셈 반올림이 없지만, 이미 옮긴 `VisitNumbers.AffordableWalletMax`에 `Math.Round`가 있다. 지금 값은 딱 떨어져 무해하나 **비율을 조정하면 갈린다** — `MidpointRounding.AwayFromZero`로 바꿔두면 영구히 안전하다

### 하지 말 것

**서버 HTTP 호출.** 예선 빌드는 오프라인이다.

### 시간

**오늘이 8/8, 예선 마감이 8/10이다.** 이게 끝나면 게임 루프가 완성되지만, **끝나지 않아도 지금 빌드로 영상은 찍을 수 있다.** 막히면 우회하지 말고 그 상태로 알려 달라 — 남은 시간에는 막힌 채로 도는 것이 제일 비싸다.

## 3-6. ⭐ 4단계 관계와 정보 공개 명세 (2026-08-08 추가)

**3-5 확인했다. 만족도 이식을 원본과 무작위 4,010건으로 대조했고 불일치 0이다** — 총점뿐 아니라 항별 점수·축 순서·거리·방향·미충족 욕구·위반 식이, 그리고 예외를 던지는 조건 990건까지 같다. `dietary_conflicts`를 재료 합집합으로 만든 것도, `MidpointRounding.AwayFromZero`로 바꾼 것도 정확하다.

물어본 넷에 답한다. **API는 주지 않는다** — 이유는 마지막에 있다.

### 답 1 — 관계 상태의 필드·범위·초기값

```
affinity     0~100 정수, 초기 0
axisHints    축별 피드백 누적 {"seasoning": 2, ...}, 초기 비어 있음
```

세이브 × 손님마다 하나씩이다.

### 답 2 — 변경 규칙

방문이 끝나면 만족도로 증감한다.

```
raw   = (만족도 - 0.4) * 20
delta = floor(raw + 0.5)
affinity = clamp(affinity + delta, 0, 100)
```

그리고 **이상 구간을 벗어난 축마다 힌트가 하나씩** 쌓인다.

**⚠️ `Math.Round`를 쓰지 마라.** 자바는 음수 절반을 0 쪽으로 올리고 C#의 `AwayFromZero`는 반대로 내려서 `-0.5`에서 갈린다. `Math.Floor(x + 0.5)`가 두 언어에서 같다.

**⚠️ 연산 순서도 명세다.** 만족 `0.375`가 경계인데, 부동소수 오차 때문에 `raw`가 정확히 `-0.5`가 아니라 아주 살짝 아래다. 같은 순서로 계산하면 두 언어가 같은 값을 내지만 순서를 바꾸면 달라진다. 고정 벡터가 이것을 잡는다.

### 답 3 — 공개 단계

| 단계 | affinity | 열리는 것 |
|---|---|---|
| `stranger` | 0~19 | 없음 |
| `familiar` | 20~59 | **평소 성향** + 피드백이 쌓인 축 |
| `regular` | 60~ | 평소 성향 + **식이 제약** + **모든 축** |

축은 따로 열린다 — 그 축이 어긋난 요리를 **3회** 받으면 그 축의 이상 구간이 공개된다. 관계가 얕아도 **관찰로** 좁혀지는 길이 있어야 취향 추론이 놀이가 된다. "좀 짠데요"를 세 번 들으면 간을 알게 되는 것이다.

### 답 4 — ⭐ 숨은 페르소나를 넘기지 않는 경계

**값이 아니라 플래그다.** 이게 네 질문 중 제일 좋은 것이었고, 답은 이렇다.

```
preferredNeeds  bool          평소 성향이 열렸는가
dietary         bool          식이 제약이 열렸는가
allAxes         bool          모든 축이 열렸는가 (단골이면 참)
revealedAxes    Set<string>   피드백으로 개별 해금된 축
```

**공개 여부만 정하고 값은 네가 자기 번들에서 읽는다.** 그래서 이쪽은 축 어휘조차 몰라도 된다 — 단골이면 `allAxes = true`라고만 하면 네가 전부 연다.

### 만족도는 이쪽에서 다시 계산하지 않는다

엔진은 **네가 소유한다**(`client-design.md` 5절). 서버가 같이 가지면 두 벌이 되고, 두 벌은 반드시 갈라진다. 경계는 이렇다.

```
네가 계산  →  만족도 · 어긋난 축
서버가 정함 →  관계 증감 · 무엇이 열리는가
```

### 무엇을 옮기나

```
domain/relationship/RelationshipRules.java     규칙
                   RelationshipNumbers.java    수치 (전부 가정값)
                   Relationship.java · Disclosure.java · Tier.java
```

**명세**: `src/test/java/.../relationship/RelationshipRulesTest.java` — **25건**. EditMode로 옮겨 전부 통과시킨다.

### ⚠️ API를 주지 않는 이유

**예선 빌드는 오프라인이라 서버를 부르지 못한다.** 지금 필요한 것은 API가 아니라 **이 규칙**이다. 영속화와 API(4-b)는 본선(9/4~6) 몫으로 미뤘다 — 오프라인 빌드가 쓰지도 못하는 것에 남은 이틀을 쓸 수 없다.

관계 상태는 `LocalDayStateStore`처럼 **한 곳에 모아** 로컬에 두어라. 서버가 붙는 날 그 자리만 바꾸면 된다.

### 시간

**오늘이 8/8, 마감이 8/10이다.** 이게 끝나면 게임 루프가 관계까지 닫힌다. **다만 지금 빌드로도 영상은 찍을 수 있다** — 이것 때문에 영상이 밀리면 안 된다. 막히면 그 상태로 알려 달라.

## 4. ⭐ 내가 당신에게 받아야 할 것 — **답 받음 (2026-08-06)**

`handoff-to-server.md`로 필드 목록이 왔다. **내가 만들어둔 것과 정확히 맞아서 재작업이 없다.** 고맙다.

받은 질문 둘에 답한다.

**enum 표기** — 요구대로 소문자 `snake_case`로 낸다. 이건 논쟁거리가 아니라 이미 계약 1-2절이다. 서버 도메인의 `enum`은 대문자지만 그 이름이 밖으로 새지 않게 API 층에서 변환한다.

**`prefers_affordable`의 출처** — 지적이 맞았고, **내 문서가 애매했던 것이 원인이다.** `server-design.md` 2절에 "서버가 고정 콘텐츠를 중계하지 않는다"고 썼는데, 그게 "읽지도 않는다"로 읽혔다. 계약 5절의 기준은 *플레이 중에 바뀌면 서버, 안 바뀌면 계약*이고 `preferred_needs`는 안 바뀌니 계약이다. **서버가 계약을 읽는 것은 금지가 아니다 — 클라에게 배달하지 않을 뿐이다.**

그래서 서버가 파이프라인 `guests.json` 스냅샷을 자기 리소스로 들고 `guest_id → prefers_affordable` 룩업을 만든다. **클라가 boolean을 실어 보내는 우회는 하지 않는다** — 그 판단도 맞았다. 그러면 클라가 부자 손님을 만들 수 있다.

그 스냅샷이 **생성분이어야 해서** 3-1절의 요청이 나왔다.

**API 명세를 넘겼다 — `docs/api.md`.** 만들어 실제로 띄우고 호출한 뒤 그 응답을 그대로 옮긴 것이다. 편지 본문에 적지 않고 문서로 넣은 이유는, 편지는 오갈 것이 끝나면 지우지만 **API 명세는 남아야 하기 때문**이다. `data-contract.md`와 같은 방식으로 **사본**이고 원본은 서버가 갖는다.

요약만 적으면 이렇다.

```
GET /api/v1/saves/{save_id}/days/{day_number}/guests/{guest_id}/visit-state
200 {"save_id":"save-1","day_number":1,"guest_id":"guest_dusty_patrol_01",
     "hunger":67,"condition":"normal","mood":"elated","wallet":24}
```

요청한 대로 키는 `snake_case`, 열거 값은 소문자다. 자바 enum 이름은 API로 새지 않는다.

**서두르지 않아도 된다.** 2단계는 임시 상태를 로컬에서 굴리기로 되어 있으니 이 API가 없어도 진행된다. 붙이는 것은 그 뒤다.

**다만 3-1절의 생성분 교체는 이 API의 전제다.** 지금 클라 번들의 `guest_id`로 부르면 전부 404가 난다 — 추측이 아니라 실제로 호출해서 확인했다.

```
GET .../guests/guest_ashen_scout_01/visit-state
404 {"error":"unknown_guest","message":"모르는 손님이다: guest_ashen_scout_01"}
```

## 5. 건드리지 말 것

- **`docs/data-contract.md`는 사본이다.** 원본은 파이프라인이 갖는다. 여기서 고치면 조용히 갈라진다. 계약을 바꿔야 할 일이 생기면 **고치지 말고 요청해라** — 그건 세 저장소가 같이 움직여야 하는 일이다
- **서버·파이프라인 코드를 이 저장소에 복사하지 마라.** 반대도 마찬가지다. 셋은 JSON 계약과 이식 명세로만 만난다

## 6. 막히면

서버가 필요해서 막히는 일은 3단계까지 없어야 한다. 그런 상황이 생기면 그건 설계가 어긋난 신호니, 우회하지 말고 알려달라.

건투를 빈다. 폰에 한글 뜨는 스크린샷을 기다리고 있겠다.
